# Return an approved design to Codex

1. Export the modified PHP, CSS and vanilla JavaScript files or provide an AI Studio GitHub revision with the source diff. Include a changed-file summary, proposed Elementor changes, asset sources and rights, review widths and known limits.
2. Approve the design direction and provide the approved logo and imagery through the private project or authorised asset channel.
3. Give Codex the design revision and have it create a dedicated redesign branch from the verified private WordPress baseline. Review the public theme diff before applying approved changes.
4. Merge presentation edits into the real theme. Reconcile CSS with existing selectors, preserve WordPress hooks and use the private asset set. Verify Elementor editing and template reuse, WooCommerce archives and product galleries, responsive tables and size guides.
5. In isolated WordPress verify catalogue search, no retail checkout, general and product enquiries, sample flows, attachments, duplicate prevention, SEO output, breadcrumbs, sitemap, mobile menus and accessibility. Re-run the private project's existing suites and capture actual rendered screenshots.
6. Build the theme and integration ZIPs with the private release pipeline and test the packages on isolated WordPress. Prepare the Hostinger staging plan with the existing backup and rollback process.
7. Review protected staging with the owner and obtain production approval through the private release workflow.

Treat AI Studio output as a proposed source revision. Private WordPress integration and staging establish backend and installability results. [WordPress integration](WORDPRESS-INTEGRATION.md)
